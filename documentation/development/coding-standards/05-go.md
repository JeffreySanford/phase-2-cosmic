# 5. Go

Go makes it easy to write fast code that silently races or leaks goroutines. These conventions keep
binaries safe and observable.

## Module & package layout

```text
tools/<service>/
  cmd/<service>/main.go   # minimal wiring
  internal/               # non-exported packages
  go.mod / go.sum         # commit go.sum
```

## Error handling

- Return errors; do not `panic` in library code (except in `init()` for must-registers).
- Wrap errors with context.
- Top-level `main` prints to stderr and `os.Exit(1)` on failure.

## Concurrency & shutdown

- Use `signal.NotifyContext` for graceful shutdown.
- Pass `context.Context` as first arg for I/O/blocking functions.
- Do not leak goroutines; each goroutine started in `main` must have a shutdown path.

## Metrics

- Register Prometheus metrics in `func init()`.
- Counter names `_total`, durations `_seconds`.
- Expose `/metrics` and `/health`.

## HTTP

- Use explicit `*http.ServeMux`, not the default.
- Set `ReadTimeout`, `WriteTimeout`, `IdleTimeout` on servers.

## Logging

- Standard `log` for simple binaries; structured logger (e.g. `log/slog`) for multi-subsystem services.
- Prefer `log/slog` for all new services.
- Never `fmt.Println` in production.

## Formatting & linting

- Run `gofmt`/`goimports` as part of CI.
- `go vet ./...` must pass.

## Testing

- Table-driven tests with `t.Run`.
- Coverage target 80%+ for `internal/` packages.
